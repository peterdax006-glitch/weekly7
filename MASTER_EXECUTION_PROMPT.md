# 4. THE MASTER CHECKLIST STATE MACHINE

Every requirement must have exactly one honest state:

```text
NOT_STARTED
IMPLEMENTED
TESTED
VALIDATED
FAILED
INSUFFICIENT_EVIDENCE
BLOCKED
```

Do not invent "basically done."

Do not use:

* nearly complete;
* essentially complete;
* practically validated;
* looks good;
* should work;
* probably works;
* complete enough.

Definitions:

### IMPLEMENTED

The actual mechanism exists.

### TESTED

Relevant tests exist, execute, and pass.

### VALIDATED

Evidence proves:

* implementation exists;
* tests pass;
* intended behavior occurs;
* correct data reaches it;
* its output reaches downstream consumers;
* provenance is valid;
* no blocking defect remains;
* the test conditions are scientifically appropriate.

### FAILED

The requirement was tested and did not meet the requirement.

### INSUFFICIENT_EVIDENCE

The implementation may work, but the evidence is not sufficient to establish that fact.

### BLOCKED

A genuine external dependency prevents testing or implementation.

A blocked item does NOT count as complete.
