# B19_find_volatility_pipeline
Bible: Find-volatility checklist V1-V5 (BIBLE.md master checklist, Phase 38) + canon C23/C24 (read canon/CANON.md). Estimated code: 1,500-3,000 lines (a requirement).
You own: engine/fv_pipeline.py, scripts/fv_eval.py, tests/test_fv_pipeline.py

Chain the existing Find-volatility pieces into ONE point-in-time weekly pipeline and measure the owner's goal: each week pick 10 stocks expected to move +-10% (movers: scripts/movers.py logic / engine.pattern_movers.PatternMoverModel), then direction at >=80% calibrated confidence (engine.direction.DirectionEngine; abstain otherwise), then exits (engine.exits) and stops (engine.stops + engine.gaprisk loss-cap filter), fills at the NEXT open (canon C33), regular hours only, no crypto. Metrics per week and per era: mover hit rate (95% target), direction accuracy on bets taken and coverage, share of the 10 finishing >= +10% (goal 8/10), worst position loss vs the -20% cap, portfolio weekly return distribution. Walk-forward only (refit on the past at each origin). Every stage can be switched off for an ablation (movers only / +direction / +exits / +stops) with bootstrap CIs over weeks. Read the named modules' public APIs first; do not edit them (list hooks). Real-data runner scripts/fv_eval.py on a seeded sample (<1.5 GB, check RAM first; background), results to state/research/fv/ with provenance. Tests with planted effects: a pipeline on synthetic data where direction is knowable must reach the goal; on noise it must abstain. Never run git.
