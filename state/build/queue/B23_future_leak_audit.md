# B23_future_leak_audit
Canon C56 (owner, verbatim - read it in canon/CANON.md): "the system should be fully oblivious to any details that would have not been available at the time its operating live ... ensure it only has live info when testing". Also C55 (must not know which year). Bible phases 1, 2, 21, 26. Estimated code: 1,500-3,000 lines (a requirement).
You own: engine/leak_audit.py, scripts/leak_audit.py, tests/test_leak_audit.py, state/research/leak_audit/. You may FIX leaks in other files only where the fix is local and fully tested; otherwise report the exact hook.

Audit EVERY channel through which a blind Test run (engine/livesim.py, scripts/livesim_loop2.py, engine/adaptive.py, engine/memory.py, patterns/bank/lessons/analogs) could know the future or recognise the year. For each: measure it on real data, write a test that FAILS when the leak exists, then fix or quarantine it. Known suspects (verify each; find more):
1. Survivorship: the universe is today's listed tickers (only 2 of 5,243 end early). Knowing a stock survives to 2026 is future info. Quantify the bias (engine/data_sources delisted registry, data/cache/delisted_*); propose/implement a point-in-time universe with a terminal-return assumption for dead names without prices.
2. Split/dividend-adjusted prices: yfinance history is back-adjusted for LATER splits (and dividends if auto_adjust). Absolute price levels, the $3 price floor, dollar-volume and any level feature then encode future splits. Detect (compare adjusted vs as-traded where possible; split history from yfinance actions) and make every level-based rule/feature split-invariant or as-traded.
3. Today's metadata: company names, SIC/sector, the crypto name filter (engine/universe, policy.not_crypto) use CURRENT data - a company that later changed business is classified by its future. Make them point-in-time or neutral.
4. Learned state from the future: basis cfg/meta, defaults from the sensitivity study, pattern bank, lessons, trust tables, gap models - are any trained on windows whose real dates are AFTER the window being played? (memory bank already filters real_end < start.) Every learned state used for window W must come only from data before W's real start. Implement the filter or report the hook in loop2 (loop2's basis training is the likely offender).
5. Macro revisions: FRED current vintage vs first release (ALFRED). Quantify for the series in use; use vintages or drop revised series.
6. Year fingerprints (C55): trading-calendar gaps (e.g. 2001 9/11 closure, 2012 Sandy, 1968 Wednesday closures), index/VIX levels, price levels, number of listed stocks, event counts - could a classifier identify the real year from what the blind feed exposes? Train one as a probe; if accuracy >> chance, normalise/scrub those channels.
7. Network: a blind worker must have NO network access (no data.update, edgar refresh, yfinance) - enforce with a guard that raises, and test it.
8. Anything else: text/news/speeches (confirm none exist in the data), file timestamps, cached results from later runs, ordering of rows by future info, labels/embargo, analog fingerprints normalised with full-sample stats, universe filters computed on future volume.
Output: state/research/leak_audit/report.md + summary.json (per channel: status LEAK/CLEAN/FIXED/QUARANTINED, evidence, test name) with provenance; a registry record. Check RAM >= 2.5 GB before real-data runs; long runs DETACHED (PowerShell Start-Process) with checkpoints. Never run git; never kill processes by name.
